## NTF 0.0 (NPC-Forge Tool calling Format)

This directory contains the modular, self-registering tool system for the TERMy agent. 

The architecture is designed to obtain total separation of concerns: a single tool file defines its own LLM schema, UI rendering configuration, and execution logic. The `__init__.py` automatically discovers and registers all tools.

### Architecture Overview

Every tool in this directory is a Python module that must expose up to three top-level objects:
1. `config` (optional): UI configuration.
2. `schema` (required): The JSON schema definition passed to the LLM to describe the tool and its parameters.
3. `execute` (required): The function containing the implementation of the tool.

The `__init__.py` checks this directory contents and automatically populates:
- `TOOLS`: A dictionary mapping tool names to their module objects.
- `TOOLS_CONFIG`: A dictionary mapping tool names to their rendering configurations.
- `_tools_map`: A dictionary mapping tool names to their JSON schemas.

---

### Tool definition

The `config` dictionary is consumed by `render_tool_action` to format the terminal output. If a key from `args` is missing, it safely resolves to an empty string.

| Key | Type | Description |
| :--- | :--- | :--- |
| `title_color` | `str` | Rich color string for the tool's title (e.g., `"red"`, `"green"`, `"cyan"`). Defaults to `"green"`. |
| `command` | `str` | A template string representing the conceptual command (e.g., `"rm {file_path}"`). |
| `description` | `str` | A template string describing the action (e.g., `"Deleting {file_path}"`). |
| `description_fallback`| `str` | A static string fallback used if `description` is empty or not provided. Defaults to `context["output"]`. |
| `response` | `str` | A template string for the main response (e.g., `"{summary}"`). Defaults to `context["output"]` if empty. |

> Note on Templates: Always use **named placeholders** (e.g., `{file_path}`) that match the keys in your tool's `args`. Positional placeholders like `{}` are not supported by the underlying `format_map` engine.

### The tool schema
The tool schema adheres to the standard OpenAI function calling format. 

The self-reflecting agentic approach requires the LLM to provide a `summary` parameter to help its future self to be able to know what to do next. If the action does not return anything or is simple enough you may provide an hardcoded summary in the tool implementation. Asking to provide a summary forces the LLM to articulate its intent before acting, which is known to improve the agent's self-reflection.

### Tool implementation
The `execute` function incapsulates the implementation of the tools:

```python
def execute(args: dict, execute: bool, context: dict, console = None, config: dict = None) -> any:
```

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `args` | `dict` | The arguments generated by the LLM based on the `schema`. |
| `execute` | `bool` | `True` if permission is granted to run, `False` otherwise |
| `context` | `dict` | The agent's persistent state |
| `console` | `Console`| A Rich `Console` object for direct terminal printing. |
| `config` | `dict` | The configuration (from `~/.local/share/termy/config.json`). |

### Managing Agent State

The `context` dictionary is the agent's memory. To prevent the LLM from getting stuck in loops, tools **must** update specific keys:

1. **`context["output"]`**: Always set this to a concise string describing the result of the tool (success or error). This is fed directly into the next LLM prompt as `"Last execution output"`.
2. **`context["summary"]`**: This is a list of strings. Append a brief, past-tense description of what was accomplished. This builds the `"Completed Actions"` list in the prompt.
3. **`context["active_file"]` / `context["active_content"]`**: If your tool modifies or reads a file, update these so the agent knows what it is currently looking at.

**Example of proper state management:**
```python
if execute and file_path:
    if target_path.exists():
        target_path.unlink()
        # 1. Update output for the LLM
        context["output"] = f"Successfully deleted {file_path}"
        # 2. Append to the historical summary
        context["summary"].append(args.get("summary", f"Deleted {file_path}"))
        # 3. Clear active file state if we just deleted it
        if context.get("active_file") == str(target_path):
            context["active_file"] = ""
            context["active_content"] = ""
```

### Best Practices for Tool Authors

1. **Always Check `execute`**: Never perform destructive or state-changing operations if `execute` is `False`. You can still validate paths or arguments and return early.
2. **Resolve Paths Safely**: Always use `Path(file_path).resolve()` to prevent directory traversal attacks (e.g., `../../../etc/passwd`).
3. **Catch All Exceptions**: Wrap your logic in a `try...except` block. If it fails, write the error to `context["output"]` and `context["summary"]` so the LLM can self-correct, rather than crashing the entire agent loop.
4. **Keep Schemas Strict**: Use `"required": [...]` in your schema to force the LLM to provide all necessary data.
5. **No Global State**: Do not rely on global variables within the tool module. All state must be passed through or returned via the `context` dictionary.

### Creating new tools

Thanks to NPC-Forge it is very easy to create a new tool:
1. Create a new file in `src/tools/`, e.g., `fetch_url.py`.
2. Define `config`, `schema`, and `execute` as shown above.
3. Add the tool's name to the `agent.tools` list in your `config.json`.

The `__init__.py` will automatically discover, register, and make it available to the agent on the next run. No imports or registries need to be manually updated.
